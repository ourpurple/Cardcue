# 架构与数据口径

## 首版

`Compose → ViewModel → BillRepository → Room`。数据库是唯一持久化来源；Room Flow 驱动页面更新，ViewModel 不持有第二份可修改余额。

账单 Statement 以账户、账单周期、币种建立唯一约束，`cardTails` 是关联卡片展示信息。首版使用固定演示账户键；真实导入前必须增加账户归属确认，尾号不能作为全局唯一账户标识。

还款 Payment 使用独立 UUID、金额（整数分）、记录时间、备注和撤销时间。撤销保留原记录，余额计算只计入未撤销记录。数据库事务内重新读取余额，拒绝零值、负数或超额还款。UI 的保存中状态防止连续点击，事务保证并发校验与写入一致。

待还 = 本期应还 - 本地有效还款记录。这个值不是银行实时余额。首次启动按当天生成演示日期，之后不重新生成或改变账单；演示种子标识与数据在同一事务中写入。

首页展示未结清账单以及每个账户/币种最新账单，保留历史欠款；已结清的旧账单在历史页面查看。人民币、美元分别汇总。首版不做汇率换算，不根据最低还款额推断免息或全部还清。

## 下一阶段

手机保管邮箱凭证并通过 IMAP 读取邮件，仅上传候选账单相关内容。后台负责文档处理和模型调用，返回结构化草稿；手机确认后入库。后台默认不长期保存正文，不在日志中输出原文或凭证。

当前 FastAPI `/health` 和 `/v1/capabilities` 不接收邮件，也未连接 App。`contracts.py` 是字段与校验草案，不是已实现的解析接口。模型“有原文依据”也不能证明提取一定正确，仍需金额、日期、账户关联规则和真实样本验证。

## 安全与数据

当前 Android Manifest 无联网权限，系统自动备份关闭。首版数据库位于 App 私有目录，尚未增加数据库级加密或导出备份。未来凭证采用 Keystore 保护，解析后台先增加设备鉴权再接收账单。

当前后台仅作为本地开发服务，默认启动绑定 127.0.0.1。不得把未加鉴权的解析能力直接暴露给公网。
