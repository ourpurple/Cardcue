# CardCue 开发计划

更新日期：2026-09-18。方向已调整为 **后台定时收邮件、统一存储与模型解析，Android 启动同步并按功能拆分**。目标架构见 [ARCHITECTURE.md](ARCHITECTURE.md)，实际结果见 [VERIFICATION.md](VERIFICATION.md)。

用户已确认以上架构并要求按计划开发。旧计划中“手机读取 IMAP、仅本地保存正式账单、仅把模型解析放后台”的路线已被替代。真实支付、商城、办卡和广告仍不在范围内。

## 本计划执行口径

| 已确认决定 | 开发任务落点 |
|---|---|
| 后台定时读取邮件 | S3：独立调度与任务进程，App 关闭仍运行 |
| 后台统一保存，手机启动同步 | S1 建权威数据库，S2 + A2 实现同步；Room 作为缓存 |
| 后台统一调用模型 | S4：模型适配、密钥、限次重试、草稿与依据 |
| 按首页、账单、账户、同步拆分 | A1：功能页面与 ViewModel 拆分，公共能力独立 |
| 独立账户、卡片、账单、来源与版本 | S1 建核心模型，S3/S4 补充邮件来源和解析关联 |

任务状态以验收证据为准：代码已编写不等于完成；尚未运行或运行失败的任务保持未勾选。后续开发按任务编号更新本文件，同时在验证记录中保存结果。

## S2 + A2：先跑通后台与手机同步

- [x] **SYNC-01** 明确 OpenAPI 契约、错误码、请求 UUID、记录版本和同步游标；合成数据先跑通账户、账单、还款。
- [x] **SYNC-02** 提供一致性分页快照和提交序号驱动的增量日志，包含变更版本与删除/归档标记；游标过期或后台恢复返回需要全量同步。
- [x] **SYNC-03** 手机启动先展示缓存，再自动同步；加入手动刷新、最后成功时间、进度和错误提示。没有缓存时同步失败不能显示零欠款。
- [x] **SYNC-04** Room 新增服务端缓存和游标，按后台实例与 Owner 隔离；本批次即编写旧库明确迁移并验证保留数据，不能等到最终联调才补迁移。快照先暂存再激活，增量数据与游标同事务提交。
- [x] **SYNC-05** 新增、撤销还款和确认命令在线提交后台，后台成功后更新缓存；离线可查看、不能写入，不乐观扣减余额。
- [x] **SYNC-06** 超时重试沿用同一 UUID；冲突刷新后核对，乱序响应不覆盖新版本，写入响应不能让同步游标跳过其他变化。
- [x] **SYNC-07** 保存设备凭证到 Keystore 保护的存储；认证失败、后台切换与设备撤销不混用缓存，也不删除旧本地待迁移记录。

**验收：** 覆盖断网、超时重试、重复保存、并发还款、设备注销、本地缓存与后台一致性验证；真机 14/14 测试通过，后台 51/51 测试通过。

## S3：后台定时收件

- [x] **S3-01** 建立独立调度与任务执行进程，不依赖 App 运行或 Web 请求触发。
- [x] **S3-02** 基于 IMAP 协议实现只读拉取与安全连接；不删除、不标记已读、不修改服务端邮件。
- [x] **S3-03** 记录邮件 UID、Message-ID、时间与摘要哈希，建立精确去重与断点续传。
- [x] **S3-04** 建立收件检查点与故障恢复；网络抖动、凭证失效、服务重启不丢件、不重复创建任务。
- [x] **S3-05** 存储原始邮件元数据与受保护正文/附件路径；对大附件与异常内容流式分片处理。
- [x] **S3-06** 区分月度账单、催款、营销与逐笔提醒，发件地址和关键词只作筛选。
- [x] **S3-07** App“刷新账单”只同步后台数据；“立即收取邮件”创建后台任务并展示进度，与定时任务共用执行机制。

**验收：** 模拟 IMAP 覆盖断线、错误凭证、重启、UID 重置、重复调度、多进程争抢与非账单过滤；使用授权邮箱验证只读行为。真实收件配置未提供时不得标记真实邮箱验收通过。

## S4：后台解析与人工确认

- [x] **S4-01** 先实现文本/HTML，再实现文本 PDF；限制大小、页数、类型和耗时，不加载远程资源或执行邮件指令。
- [x] **S4-02** OCR、加密附件作为单独子任务；不支持或解密失败进入明确的人工处理状态。
- [x] **S4-03** 后台统一模型适配与密钥配置；严格输出校验、输入/配置指纹缓存、限次重试和调用不确定状态，防止无界重试费用。
- [x] **S4-04** 完善 StatementDraft 和 Evidence：缺失不填 0，最低还款额有值但无依据须提示复核，仅有尾号不能代表账户已关联。
- [x] **S4-05** 手机展示原文依据、账户选择、人工修改和确认；后台校验版本及规则后事务内生成正式账单版本。
- [x] **S4-06** 补发关联已有版本，更正版保留来源与修改历史；不静默覆盖人工修正，不重复累加欠款。
- [x] **S4-07** 定义受保护原文/附件保留与清理策略，过期依据明确提示；日志不包含正文或凭证。

**验收：** 建立多银行脱敏标注集，逐字段验证金额、币种、日期、账户、缺失与冲突。覆盖非 JSON、虚假依据、提示注入、超时、供应商异常、重复确认和版本冲突。模型输出不直接成为正式债务。
