# CardCue 开发计划

更新日期：2026-09-17。方向已调整为 **后台定时收邮件、统一存储与模型解析，Android 启动同步并按功能拆分**。目标架构见 [ARCHITECTURE.md](ARCHITECTURE.md)，实际结果见 [VERIFICATION.md](VERIFICATION.md)。

用户已确认以上架构并要求按计划开发。旧计划中“手机读取 IMAP、仅本地保存正式账单、仅把模型解析放后台”的路线已被替代。真实支付、商城、办卡和广告仍不在范围内。

## 本计划执行口径

| 已确认决定 | 开发任务落点 |
|---|---|
| 后台定时读取邮件 | S3：独立调度与任务进程，App 关闭仍运行 |
| 后台统一保存，手机启动同步 | S1 建权威数据库，S2 + A2 实现同步；Room 作为缓存 |
| 后台统一调用模型 | S4：模型适配、密钥、限次重试、草稿与依据 |
| 按首页、账单、账户、同步拆分 | A1：功能页面与 ViewModel 拆分，公共能力独立 |
| 独立账户、卡片、账单、来源与版本 | S1 建核心模型，S3/S4 补充邮件来源和解析关联 |

任务状态以验收证据为准：代码已编写不等于完成；尚未运行或运行失败的任务保持未勾选。后续开发按任务编号更新本文件，同时在验证记录中保存结果。

## S1：后台业务与存储基础

- [ ] **S1-01** 引入 PostgreSQL、SQLAlchemy 2、Alembic；定义服务端配置与数据库会话，提供空库初始化和升级说明。
- [ ] **S1-02** 建立 Owner/Device、Account、Card、Statement、StatementCard、StatementVersion、Payment 等实体和约束；草稿、来源关联与变更日志按相应批次明确迁移。
- [ ] **S1-03** 将账户身份、账期、币种与版本独立建模，避免尾号合并账户或共享卡重复计账；明确欠款、溢缴款、缺失金额及跨期结转口径。
- [ ] **S1-04** 提供账户/卡片维护、账单查询与版本、还款记录和撤销的服务层与 API；首批测试账单通过合成 fixture 创建，不新增不受控的原文导入入口。
- [ ] **S1-05** 使用事务锁和实际剩余金额校验并发还款；请求 UUID 幂等，撤销留痕；更正版本不能静默使有效还款超过应还。
- [ ] **S1-06** 建立设备配对、令牌摘要存储、撤销与归属校验。远程访问先具备 HTTPS 和请求限制。
- [ ] **S1-07** 写入与变更日志在同一事务提交，使用可安全表示提交顺序的 Owner 级序号，为同步协议准备基础。

**验收：** 在真实 PostgreSQL 测试实例上验证迁移、唯一约束、事务回滚、并发全额还款、重复请求、重复撤销、错误归属与设备失效；不能仅用 SQLite 测试代替数据库锁语义。

## S2 + A2：先跑通后台与手机同步

- [ ] **SYNC-01** 明确 OpenAPI 契约、错误码、请求 UUID、记录版本和同步游标；合成数据先跑通账户、账单、还款。
- [ ] **SYNC-02** 提供一致性分页快照和提交序号驱动的增量日志，包含变更版本与删除/归档标记；游标过期或后台恢复返回需要全量同步。
- [ ] **SYNC-03** 手机启动先展示缓存，再自动同步；加入手动刷新、最后成功时间、进度和错误提示。没有缓存时同步失败不能显示零欠款。
- [ ] **SYNC-04** Room 新增服务端缓存和游标，按后台实例与 Owner 隔离；本批次即编写旧库明确迁移并验证保留数据，不能等到最终联调才补迁移。快照先暂存再激活，增量数据与游标同事务提交。
- [ ] **SYNC-05** 新增、撤销还款和确认命令在线提交后台，后台成功后更新缓存；离线可查看、不能写入，不乐观扣减余额。
- [ ] **SYNC-06** 超时重试沿用同一 UUID；冲突刷新后核对，乱序响应不覆盖新版本，写入响应不能让同步游标跳过其他变化。
- [ ] **SYNC-07** 保存设备凭证到 Keystore 保护的存储；认证失败、后台切换与设备撤销不混用缓存，也不删除旧本地待迁移记录。

**验收：** 两个独立客户端验证并发、重复提交与一致性；覆盖分页期间并发写入、断网、中断恢复、重复页、空快照、过期游标、删除标记、服务器恢复及令牌失效。后台故障时可查看明确标记为缓存的旧数据。

## S3：后台定时收取新浪邮件

- [ ] **S3-01** 提供独立调度器与任务进程；默认每 30 分钟、可配置，手机关闭仍能收件，不在每个 API worker 中创建调度器。
- [ ] **S3-02** 持久化 Job、Mailbox、MailCursor、EmailSource、Attachment；邮箱级租约、任务唯一键、检查点与退避重试防止重叠执行。
- [ ] **S3-03** 邮箱凭证后台加密存储，主密钥与数据库分离；不进入手机、Git、日志或任务错误详情。
- [ ] **S3-04** TLS 验证、只读 IMAP；首次三个月，后续邮箱 + 文件夹 + UIDVALIDITY + UID 增量，抓取不改已读、不移动或删除邮件。
- [ ] **S3-05** 保存内容指纹，区分邮件去重、业务重复与更正版；UIDVALIDITY 变化可重建进度并避免重复账单。
- [ ] **S3-06** 区分月度账单、催款、营销与逐笔提醒，发件地址和关键词只作筛选。
- [ ] **S3-07** App“刷新账单”只同步后台数据；“立即收取邮件”创建后台任务并展示进度，与定时任务共用执行机制。

**验收：** 模拟 IMAP 覆盖断线、错误凭证、重启、UID 重置、重复调度、多进程争抢与非账单过滤；使用授权邮箱验证只读行为。真实收件配置未提供时不得标记真实邮箱验收通过。

## S4：后台解析与人工确认

- [ ] **S4-01** 先实现文本/HTML，再实现文本 PDF；限制大小、页数、类型和耗时，不加载远程资源或执行邮件指令。
- [ ] **S4-02** OCR、加密附件作为单独子任务；不支持或解密失败进入明确的人工处理状态。
- [ ] **S4-03** 后台统一模型适配与密钥配置；严格输出校验、输入/配置指纹缓存、限次重试和调用不确定状态，防止无界重试费用。
- [ ] **S4-04** 完善 StatementDraft 和 Evidence：缺失不填 0，最低还款额有值但无依据须提示复核，仅有尾号不能代表账户已关联。
- [ ] **S4-05** 手机展示原文依据、账户选择、人工修改和确认；后台校验版本及规则后事务内生成正式账单版本。
- [ ] **S4-06** 补发关联已有版本，更正版保留来源与修改历史；不静默覆盖人工修正，不重复累加欠款。
- [ ] **S4-07** 定义受保护原文/附件保留与清理策略，过期依据明确提示；日志不包含正文或凭证。

**验收：** 建立多银行脱敏标注集，逐字段验证金额、币种、日期、账户、缺失与冲突。覆盖非 JSON、虚假依据、提示注入、超时、供应商异常、重复确认和版本冲突。模型输出不直接成为正式债务。
