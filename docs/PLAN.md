# CardCue 开发计划

## 已确认的产品范围

个人自用、Android 手机、新浪邮箱、手动同步、多家银行、后台大模型解析。首页参考用户提供的信用卡列表，保留账单、还款日期与还款记录功能。

## 阶段一：本地账单版本（当前）

- [x] 原生 Android 工程及 FastAPI 骨架源码。
- [x] 首页、详情、历史、设置及演示状态说明源码。
- [x] Room 账单与还款记录，交易内金额校验、撤销留痕源码。
- [x] 按账户统计，共用账单不按卡片重复求和；按币种分别汇总。
- [x] 编写金额、日期、数据库持久化、并发还款和 UI 流程测试。
- [x] 后台自动化测试通过。
- [ ] Gradle 单元测试、Lint 和 APK 构建通过。
- [ ] 模拟器/真机验证页面、字体缩放、返回导航和数据库重启读取。
- [ ] 将完整工程放入用户指定的 `D:\code\cardcue`。

阶段一的验收：安装到手机，查看账单详情，记录一笔部分还款，重启后仍存在，再撤销并恢复待还金额。当前不能仅凭源码检查认定通过。

## 阶段二：新浪邮箱与智能解析

1. 手机端接入 IMAP：TLS、客户端授权码、Android Keystore 保护凭证、不修改已读状态、不删除邮件。
2. 首次最近三个月，后续增量同步；以邮箱账户 + 文件夹 + UIDVALIDITY + UID 跟踪邮件，另保存邮件内容指纹作业务去重。
3. 明确用户触发的同步生命周期：收取在手机执行，网络失败可重试，状态持久化，中断后继续。
4. 分类区分月度账单、催款、营销、逐笔交易提醒。发件地址和关键词只作筛选，不单独作为真实性证明。
5. HTML 正文清理、PDF 文本提取，扫描件 OCR；加密附件进入单独处理流程，不上传不必要的解密信息。
6. 后台增加设备鉴权、HTTPS、请求大小限制和超时；对接可替换的模型供应商。密钥只在服务端配置。
7. 邮件内容视作不可信数据，不允许指挥工具执行或改变解析任务。模型严格输出结构化草稿和原文依据。
8. 缺失、冲突、多卡账户归属、负余额/溢缴款、更正版账单等进入人工确认，不能直接套用当前非负演示账单模型。
9. 确认后保存账单；人工修正优先，后续同步不静默覆盖。补发与更正版保留来源和版本。
10. 用用户提供的多银行脱敏样本逐字段验收。样本中出现的多币种、跨年日期和共享账户必须覆盖。

## 阶段三：日常使用

- 还款前提醒：权限、重启恢复、日期变化、设备省电策略下的行为说明。
- 手动加密导出/恢复：文件版本、完整性验证、密钥管理、原子恢复。
- 演示数据与真实数据切换：不混入真实待还合计，不覆盖真实账单。
- 解析调用耗时和费用记录（不记录邮件正文）、失败重试及数据删除。

## 以后可扩展

POP3 兼容、逐笔交易明细、消费分类、统计分析。真实支付、商城、办卡、广告不在本项目当前范围内。
